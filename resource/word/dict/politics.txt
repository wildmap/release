# 涉政（违法信息，整条拒收）
#
# **本文件在代码仓里刻意保持为空**，词条由运维在部署期投放，不入版本库。
#
# 三个理由：
#   1. 该类目的判定边界由监管口径决定且随时间变动，仓库里的静态列表必然滞后；
#   2. 把具体词面写进代码仓、日志与测试用例本身就构成传播风险，而且会随 git
#      历史永久留存，事后删不掉；
#   3. 这类词表的漏报与误报都要对外承担责任，必须有可追溯的来源，不能由研发
#      凭印象编写。
#
# 代码侧只保留三样东西，它们都已经就位：
#   - 分类枚举 xword.CatPolitics（见 pkg/xword/category.go）
#   - 加载入口：本文件被 xword.LoadFS 按文件名识别为 politics 分类
#   - 处置策略：Category.Illegal() 为真 → 整条拒收（见 chat/logic.FilterChatText）
#
# 正式词表从内容安全供应商或主管部门下发渠道获取，放到磁盘资源目录的同名路径
# 覆盖本文件即可（resource/ 的磁盘覆盖机制见 resource.Init），不必改代码、
# 不必重新编译。
#
# 运营建议：涉政命中不要接自动封禁，一律走「拦截 + 转人工复审」——该类目误伤
# 后的用户体感与舆情成本远高于其它类目。同时所有 UGC 入口（聊天、昵称、群名、
# 举报理由）都要接同一份词表，而不是只过滤聊天。
